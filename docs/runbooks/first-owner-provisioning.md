# Создание организации и первого владельца

Этот порядок выполняет только platform owner — технический владелец платформы.
Company owner, администратор и менеджер не могут создавать организации или первые учётные записи.

## 1. Создать организацию

Отправьте запрос `POST /platform/organizations` с platform-owner bearer-токеном:

```json
{
  "organization_name": "Название компании",
  "owner_email": "owner@company.example"
}
```

Ответ возвращает `organization_id`, e-mail и `setup_token`. Токен показывается только в этом ответе и действует 48 часов.

## 2. Передать токен владельцу компании

Передавайте `setup_token` только через согласованный защищённый канал. Не отправляйте его в общих чатах, тикетах, Google Sheets, e-mail-пересылках или скриншотах.

Если токен скомпрометирован, просрочен или использован, не пытайтесь применять его повторно: создайте новое приглашение через предусмотренный административный поток.

## 3. Активировать доступ

Первый владелец отправляет токен и новый пароль в `POST /auth/setup`:

```json
{
  "setup_token": "полученный_одноразовый_токен",
  "password": "пароль_не_короче_12_символов"
}
```

Успех возвращает два значения: `enrollment_token` и `totp_uri`. После этого setup-токен нельзя использовать повторно. При ошибке API намеренно не сообщает, истёк ли токен, уже использован или неверен.

## 4. Подключить приложение-аутентификатор

1. Откройте приложение-аутентификатор (например, 1Password, Google Authenticator или Microsoft Authenticator) и добавьте новую запись по QR-коду или `totp_uri`.
2. Сразу отправьте полученный шестизначный код вместе с `enrollment_token` в `POST /auth/totp/confirm`:

```json
{
  "enrollment_token": "полученный_одноразовый_токен",
  "code": "123456"
}
```

3. Успешный ответ единственный раз возвращает `recovery_codes`. Скопируйте их в автономное защищённое хранилище команды (например, корпоративный password manager). После закрытия или обновления страницы API уже не покажет те же коды.

Только после этого владелец сможет войти с e-mail, паролем и TOTP-кодом. Для привилегированных ролей сессия не выдаётся без второго фактора.

## Что запрещено

- Не передавайте platform-owner bearer-токен сотрудникам.
- Не сохраняйте setup-токен, enrollment-токен, пароль, TOTP-коды, `totp_uri` или recovery-коды в GitHub, `.env.example`, документации и таблицах.
- Не создавайте общий аккаунт для нескольких сотрудников: у каждого должна быть собственная учётная запись и сессия.
